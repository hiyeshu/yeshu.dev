我以前会把 skill 理解成一个高级 prompt 包。

现在觉得不太对。

它更像 agent 世界里的二维码。

二维码那张黑白小图，本身没什么可看的。没人会盯着二维码研究构图。它的价值在于：用一个很小、标准化、机器能识别的码，把人带到一个更大的东西里。

扫一下，可能打开一个网页。

扫一下，可能调起付款。

扫一下，可能进入点餐系统、会员页、表单、地图、客服。

二维码不是内容。

二维码是入口。

Skill 也是这样。

一个 skill 最小就是一个文件夹，里面有个 `SKILL.md`。文件开头的 YAML 可能只有两行：

```yaml
name:
description:
```

就这么点东西。

Agent 启动时，不会把整个 skill 都塞进系统提示里。它只会先看到这些元数据：名字、描述、触发范围。几十个 token，挂在那里。

这很像墙上贴了一排二维码。

用户说了一句话，agent 判断这件事和某个 skill 有关，才会去“扫码”。扫完以后，完整的说明、流程、脚本、模板、CLI、参考资料才展开。

所以 skill 的关键不是里面写了多少 prompt。

关键是它能不能被正确扫到。

一个二维码如果贴错地方，再好的页面也没人打开。一个 skill 如果 `name` 和 `description` 写得不准，里面塞再多流程也没用。agent 根本不会调用它。

这也是我觉得 skill 有意思的地方。

它不是单纯的提示词。

它是一种入口设计。

餐厅把二维码贴在桌上，用户扫码点菜。那个二维码不只是工具，它也改变了餐厅的服务流程。前台少问一句，后厨早知道一秒，套餐可以被放在更显眼的位置，会员系统也可以顺手接上。

二维码一旦稳定，就不只是入口。

它会变成业务的一部分。

Skill 也会这样。

一开始，大家会把 skill 当便利工具：写报告、查代码、生成图片、整理项目、跑脚本。

但再往后，它会变成一种分发方式。

你写一个 skill，不只是写一段 prompt。你是在定义一个场景：

谁会在什么时候需要你。

Agent 在什么任务里会想起你。

你提供什么能力。

调用之后，用户看见什么动作。

这就有商业价值了。

因为入口本来就是内容的一部分。

一个 skill 里可以放自己的 CLI。可以放品牌说明。可以放服务入口。也可以放一句赞助信息或付费说明。

这件事比“在模型里塞广告”更容易被接受。

模型里硬塞广告，会让人烦。因为用户没有请求，模型也没有理由。对话本来在解决问题，突然跳出一张传单，信任就坏了。

但 skill 不一样。

Skill 是用户主动安装的。它有名字，有描述，有文件夹，有边界。用户知道自己扫的是谁家的码。

你在 skill 里放一个自己的 CLI，就像在工具箱里放了一把你做的刀。

你在 skill 里放一个 sponsor 链接，就像开源项目 README 里写赞助入口。

这不是偷偷污染模型。

这是在一个明确入口里表达自己。

当然，边界也在这里。

广告不能伪装成能力。

推广不能压过任务。

Skill 不能把用户带去和当前问题无关的地方。

二维码可以贴在菜单上。

但用户扫菜单，结果跳出贷款页面，那就不是入口设计，是欺骗。

好的 skill 应该像好的二维码：

小。

清楚。

能扫。

扫完有用。

它不需要在入口处解释一切。

它只需要让 agent 一眼知道：

什么时候该打开它。
